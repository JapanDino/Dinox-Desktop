# Задачи календарей и создание записей

Состояние на 28 сентября 2026. Код и браузерные сценарии реализованы. Google OAuth-приложение издателя зарегистрировано в проекте `dinox-desktop`: клиент **Dinox Desktop Windows** (Desktop app), Calendar API и Tasks API включены, три используемых scope настроены. Режим — **External / In production**, бесплатный пилот до 100 пользователей; публичная проверка Google не пройдена. См. [GOOGLE-PILOT.md](GOOGLE-PILOT.md). Настоящий OAuth-вход, чтение календарей/задач, обновление токена, создание timed/all-day событий и dated/undated задач, завершение и возврат задач в работу проверены через штатный Rust-код на реальном Google-аккаунте. Установленный Dinox не обновлялся; полный путь через кнопки установленного приложения не проверен. Подробности: [GOOGLE-LIVE-VALIDATION.md](GOOGLE-LIVE-VALIDATION.md).

## Что доступно в коде

- Разбор VTODO в ICS: срок с датой или временем, задачи без срока, выполненные задачи, повторения, исключения, отменённые и перенесённые экземпляры. Задача отображается по сроку DUE (или DTSTART, если срока нет), а не как многодневная встреча. ICS остаётся только для чтения.
- Отдельный список «Задачи» в календаре и в панели виджетов: поиск, выполненные, задачи без срока. Длинные списки выводятся порциями по 60 строк. Локальные задачи виджета сохраняются отдельно.
- Форма «Событие / Задача»: выбор доступного для записи календаря, название, описание, дата, весь день или время. Дата окончания события в интерфейсе включительная; API получает исключительную конечную дату.
- Google Calendar API: чтение событий, создание событий с временем или на весь день. Загружаемый диапазон — год назад и два года вперёд; пагинация ограничена 15 000 записей на коллекцию.
- Google Tasks API: чтение всех списков, в том числе выполненных, скрытых и назначенных задач; создание с датой или без даты; завершение и возврат в работу. Точное время задачи API не предоставляет: для встречи с временем нужно явно выбрать «Событие».
- Яндекс: подготовлены обнаружение CalDAV-коллекций, чтение, создание VEVENT/VTODO через PUT с If-None-Match. Задачи предлагаются только при объявленном сервером VTODO. Изменение статуса задачи Яндекса из Dinox пока не поддерживается.
- Вход Google: внешний браузер, PKCE S256, случайный state и временный localhost-порт. Вход Яндекса: device flow с вводом короткого кода на странице провайдера; возможность доступа OAuth к CalDAV обычного потребительского аккаунта ещё требует проверки.
- Токены и кэш хранятся в `calendar-accounts.bin`, зашифрованном Windows DPAPI. Токены не передаются React. HTTP-ошибки не включают тела ответов или приватные URL; редиректы отключены. CalDAV-ссылки разрешены только на HTTPS caldav.yandex.ru:443.
- Перед записью сохраняется журнал запросов. После тайм-аута/неясного ответа повтор с тем же ID не отправляется автоматически. Пользователю предлагается проверить исходный календарь. «Создано» появляется только после подтверждения; сбой обновления списка после успешной записи не вызывает повторного создания.
- Отключение аккаунта удаляет локальные данные подключения, но не события у провайдера. Для отзыва разрешения на стороне сервиса используется управление доступом в аккаунте провайдера.

## Подключение для обычного пользователя

Целевой путь: «Подключить Google» → выбрать аккаунт → разрешить доступ → выбрать календарь. Пользователь не создаёт Cloud-проект и не вводит Client ID, секреты либо пароли в Dinox. Секретная ICS-ссылка остаётся простым вариантом только для чтения.

Пока данные приложения издателя не заданы при сборке, кнопка входа отключена с понятным объяснением. В браузерном стенде `personal-preview.html?calendar-sync` аккаунт и ответы API синтетические. Это не подключение настоящего Google.

## Однократная настройка издателем (не пользователем)

### Google

1. Зарегистрировать собственный проект Dinox и включить Google Calendar API и Google Tasks API.
2. Настроить OAuth consent screen: имя Dinox, контакт поддержки, собственный домен и политика конфиденциальности. Создать OAuth-клиент типа **Desktop app**.
3. Запросить только используемые права: `calendar.calendarlist.readonly`, `calendar.events`, `tasks`. Подготовить необходимые Google проверку приложения и разрешений для публичного распространения; тестовый режим не считать публичным релизом.
4. Перед Rust-сборкой передать `DINOX_GOOGLE_CLIENT_ID` и выданный Desktop-клиенту `DINOX_GOOGLE_CLIENT_SECRET` через окружение сборки. Не добавлять реальные значения в Git, документацию, фронтенд или логи. Секрет, включённый в распространяемое desktop-приложение, **не является конфиденциальным серверным секретом**; безопасность входа опирается на PKCE и согласие пользователя.
5. На отдельном тестовом аккаунте проверить первый вход, отказ, отмену, частичные права, повторный вход, истечение и отзыв токена, перезапуск приложения и сохранность кэша. Создать и перечитать тестовые timed/all-day события и dated/undated задачи, отметить и снять выполнение. Проверить отключение аккаунта.

Локально для издателя подготовлен `scripts/load-google-oauth.ps1`. Перед сборкой выполнить `. ./scripts/load-google-oauth.ps1` в том же PowerShell-процессе. Он читает Desktop-реквизиты из `%LOCALAPPDATA%\Dinox\publisher\google-oauth.json` и задаёт OAuth-реквизиты и режим доступа в окружении процесса без печати секретных значений. Путь можно переопределить параметром `-CredentialsPath`. Файл реквизитов находится вне репозитория; права папки ограничены текущим пользователем и SYSTEM. В CI значения нужно передавать отдельно через секреты сборки; этот локальный файл не публикуется.

Аккаунт владельца добавлен в список тестовых пользователей. После загрузки реальной конфигурации издателя повторно выполнена release-компиляция и 7 Rust-тестов `calendar_sync` — все прошли. Отдельные игнорируемые по умолчанию live-тесты подтвердили настоящий OAuth и запись в Google. Для публичного подключения ещё нужны завершённый Branding (сайт и политика конфиденциальности) и требуемая Google проверка.

### Яндекс

1. Зарегистрировать приложение Dinox в Яндекс OAuth и подтвердить доступ именно к CalDAV обычного пользовательского аккаунта. Документация сервисных приложений Яндекс 360 для бизнеса сама по себе этого не доказывает.
2. Проверить device authorization и `Authorization: OAuth` с CalDAV, объявленные компоненты и права на тестовом календаре. Если VTODO не объявлен, задачи Яндекса не обещать.
3. Только после успешной проверки задать `DINOX_YANDEX_CLIENT_ID`, `DINOX_YANDEX_CLIENT_SECRET`, `DINOX_YANDEX_CALDAV_APPROVED=true` для сборки. До этого кнопка остаётся отключённой. Для подключения по ссылке эта настройка не нужна.

## Границы текущей реализации

- Подписка ICS не предоставляет права записи и не гарантирует включение Google Tasks.
- Нет автоматического повторения неподтверждённых записей и фоновой очереди создания без интернета; черновик остаётся в открытой форме.
- Создание повторяющихся задач/событий, редактирование и удаление уже существующих записей пока не реализованы. Google Tasks API также не переносит время и настройки повторений из интерфейса Google Calendar.
- Не поддерживаются вложения и участники встреч; создание не отправляет приглашения.
- До 8 аккаунтов, кэш до 64 МБ, журнал до 2 000 запросов. При достижении границы показывается ошибка, данные молча не отбрасываются.
- Обновление по общему расписанию: 10 минут, в экономном режиме 30; доступна ручная кнопка.
- Реальный аккаунт Google и Windows DPAPI между запусками тестового процесса проверены. Отзыв разрешений, частичное согласие, тайм-ауты сети при записи и весь установленный интерфейс пока не проверены с реальным аккаунтом. Яндекс live-проверку не проходил.

- `bun test`: 78 тестов / 1203 проверки, включая 10 новых сценариев задач.
- `bun run build`: TypeScript и production bundle.
- `cargo test --release --locked --offline --manifest-path src-tauri/Cargo.toml --bin bloom calendar_sync`: 7 протокольных и граничных тестов без запуска интерфейса Dinox.

- `tests/calendar-compact.browser.mjs`: 6 проверок компактной карточки, раскрытия деталей, сохранности полей, клавиатуры и узкого окна. Базовая карточка — 440 × 354 px; описание и дата окончания скрыты в «Деталях».
