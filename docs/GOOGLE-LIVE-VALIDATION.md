# Реальная проверка Google Calendar и Tasks

Дата: 28 сентября 2026. Проект Google: `dinox-desktop`, клиент Desktop app.

## Метод

С явным согласием владельца выполнены OAuth-вход и работа с его Google-аккаунтом. Использован штатный Rust-код `calendar_sync::google`, а не повторная реализация API в скрипте. Функция открытия браузера отделена от общей OAuth-логики: обычное приложение по-прежнему использует Tauri Opener и 180-секундное ожидание; тест сохраняет ссылку для браузера и ждёт до 15 минут. Интерфейс оболочки и панели Windows не запускались.

Тесты `live_google_*` имеют `#[ignore]` и дополнительное требование `DINOX_LIVE_TEST=google`. Обычный запуск тестов не обращается к аккаунту. Для live-запуска нужно заранее загрузить конфигурацию издателя через `. ./scripts/load-google-oauth.ps1`.

## Подтверждено

- OAuth с PKCE и localhost callback: Google выдал токены, серверный обмен завершён успешно.
- Чтение календарей, событий, списков задач и задач через реальный API.
- Сохранение аккаунта с Windows DPAPI и чтение из другого тестового процесса.
- Принудительное обновление access token через refresh token.
- Создание и отдельное GET-чтение события на 12:00–12:30 UTC+3: совпадают название, начало и конец с учётом часового пояса.
- Создание и GET-чтение события на весь день: совпадают даты, конец исключительный.
- Создание и GET-чтение задачи с датой и задачи без даты.
- Завершение и возврат в работу обеих задач: каждый переход подтверждён GET-запросом.
- В конце roundtrip Google подтвердил удаление всех четырёх созданных записей; ошибок очистки нет.
- Отдельный read-only тест после завершения roundtrip подтвердил GET-запросами: все 4 тестовые записи удалены или отменены, активных тестовых записей не осталось.

Все записи получили уникальный префикс `[Dinox TEST <run-id>]`; запросы изменения и удаления направлялись только на сохранённые ID этих записей. Отчёты не содержат пользовательских событий или токенов. Подключение и журнал очистки хранятся зашифрованными в `%LOCALAPPDATA%\Dinox\publisher\live-test`, вне репозитория и отдельно от установленного приложения.

## Воспроизведение

Из подготовленной MSVC/Rust среды, после загрузки конфигурации издателя и установки `DINOX_LIVE_TEST=google`:

```powershell
cargo test --release --locked --offline --manifest-path src-tauri/Cargo.toml --bin bloom live_google_login -- --ignored --nocapture --test-threads=1
cargo test --release --locked --offline --manifest-path src-tauri/Cargo.toml --bin bloom live_google_roundtrip -- --ignored --nocapture --test-threads=1
cargo test --release --locked --offline --manifest-path src-tauri/Cargo.toml --bin bloom live_google_verify_cleanup -- --ignored --nocapture --test-threads=1
```

Первый тест требует открытия приватной ссылки `authorize-url.txt` и согласия владельца в Google. Второй создаёт четыре временные записи и удаляет их. Третий только проверяет сохранённые ID на отсутствие активных записей.

## Границы проверки

Это реальная проверка OAuth и нативного адаптера Google, но не end-to-end проверка установленного интерфейса Dinox, его Tauri-команд и журнала идемпотентности. Не проверены отзыв доступа, частичные разрешения, длительная работа, сетевые сбои в момент записи и интеграция Яндекса. Установленная версия не менялась. На момент этого теста Google-приложение было External / Testing. Позднее оно переведено в In production для непроверенного пилота; актуальные ограничения — в GOOGLE-PILOT.md.
